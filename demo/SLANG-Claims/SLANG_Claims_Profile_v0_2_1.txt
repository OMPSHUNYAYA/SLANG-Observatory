This profile defines a bounded structural claim-payability reference.
It does not authenticate sources, establish real-world loss, interpret policy or law, determine fraud, settle claims, authorize payment, or move money.

2. CENTRAL CONTRACT

`declared claim context + bound claim-authority evidence + versioned rules -> bounded claim-payability state`

For admitted canonical structure:

`same admitted canonical structure + same versioned contract -> same bounded result`

3. AUTHORITY EXCLUSIONS

`payment_authority = NONE`
`settlement_authority = NONE`
`legal_authority = NONE`
`policy_interpretation_authority = NONE`
`fraud_determination_authority = NONE`
`money_movement = NONE`

No result, receipt, attestation, contract identity, or authenticity envelope changes these exclusions.

4. SUPPORTED RESOLUTION STATES

`RESOLVED`
`INCOMPLETE`
`CONFLICT`
`FORBIDDEN`
`UNSUPPORTED`
`ABSTAIN`

Primary-state precedence:

`FORBIDDEN > CONFLICT > UNSUPPORTED > INCOMPLETE > ABSTAIN > RESOLVED`

5. OUTCOMES AND ADMISSION

Resolved outcomes:

`PAYABLE`
`NOT_PAYABLE`

Non-result outcome symbol:

`NONE`

Admission symbols:

`ADMIT`
`DENY`
`WITHHOLD`

Mapping:

`RESOLVED + PAYABLE -> ADMIT`
`RESOLVED + NOT_PAYABLE -> DENY`
`non-result state -> WITHHOLD`

6. EVIDENCE MODES

`SINGLE_AUTHORITY`

Exactly one expected authority and exactly one evidence record.

`MULTI_AUTHORITY_EXACT_AGREEMENT`

Two or more expected authorities are supported within resource limits. Every expected authority must be present exactly once. Admitted evidence must agree exactly on coverage, occurrence, exclusion, control, and assessed loss.

`exact agreement -> continue`
`material disagreement -> ABSTAIN`

No voting, averaging, authority ranking, majority selection, or first-arrival rule is used.

7. EVALUATION AUTHORITY

If `evaluation_authorized = false`, the primary state is `ABSTAIN` unless a higher-precedence structural issue is present.

`evaluation not authorized -> ABSTAIN`

The `conflicts` diagnostic list contains only locations classified as `CONFLICT`. An `ABSTAIN` reason is carried by the state and `reason_codes` and is not mislabeled as a conflict.

This is distinct from `FORBIDDEN`, which is reserved for prohibited material or caller-supplied derived authority/outcome fields.

8. BINDING

Each admitted evidence record is bound to the normalized claim context, including:

- evaluation identifier
- claim reference
- policy reference
- claimant reference
- loss-event reference
- currency
- authority identity
- evidence mode

A supported binding mismatch is `CONFLICT`.

9. QUANTUM PROFILE

Let:

`C = claim_amount_minor`
`A = assessed_loss_minor`
`D = deductible_minor`
`L = remaining_limit_minor`

Then:

`admitted_loss_minor = min(C, A)`
`post_deductible_minor = max(admitted_loss_minor - D, 0)`
`payable_amount_minor = min(post_deductible_minor, L)`

Equivalent:

`payable_amount_minor = min(max(min(C, A) - D, 0), L)`

This arithmetic is specific to `CLAIM-QUANTUM-NET-AFTER-DEDUCTIBLE-CAP-1` and is not universal insurance mathematics.

10. MONEY REPRESENTATION

Supported bounded monetary values use integer minor units.

`0 <= money_minor <= 9007199254740991`

Binary floating-point money is not part of this profile.

11. CANONICALIZATION AND IDENTITIES

The reference uses `SLANG-CANONICAL-JSON-1-D02`.

Supported set-like structures are normalized where declared, including JSON object key order, expected authority order, and evidence-record presentation order.

The reference constructs domain-separated SHA-256 identities for contract, input, context, authority manifest, evidence, agreement, rule profile, outcome, result, bundle, receipt, summary, attestation, and vector material.

`identity of structure != source authenticity`

12. STRICT JSON BOUNDARY

Principal limits:

`MAX_JSON_INPUT_BYTES = 1048576`
`MAX_JSON_DEPTH = 48`
`MAX_JSON_NODES = 50000`
`MAX_LIST_LENGTH = 256`
`MAX_STRING_LENGTH = 1024`
`MAX_IDENTIFIER_LENGTH = 128`
`MAX_EVIDENCE_RECORDS = 8`
`MAX_REASON_CODES = 64`
`MAX_SAFE_INTEGER = 9007199254740991`

The parser rejects duplicate JSON object keys, floats, non-finite numbers, invalid UTF-8 file input, unsupported JSON classes, non-string object keys, excessive depth, excessive node counts, oversized strings/lists, and nonportable integers.

The public library entry point applies `validate_portable_json(raw_input)` before forbidden-field scanning or any other recursive domain inspection. Therefore the same depth, node, string, list, type, and portable-integer limits apply whether input arrives through the CLI parser or as a hand-built Python value.

`library entry -> portable/resource validation -> recursive domain inspection`

13. FIELD ADMISSION AND FORBIDDEN-NAME DEFENSE

Exact supported-field sets are the primary admission gate.

Unknown fields are not silently ignored.

Forbidden-name recognition is defense in depth. It derives ASCII separated and compact signatures so separator, camelCase, and compact spellings can map to one forbidden field family.

Examples:

`bank_account`
`bank-account`
`bankAccount`
`bankaccount`

`strict allowlist = primary gate`
`forbidden-name recognition = defense-in-depth classification`
`field-name recognition != secret-content detection`

Values under recognized forbidden field names are replaced by `<FORBIDDEN_VALUE_REDACTED>` before the structural submission commitment is computed. The reference therefore does not create distinct submission digests solely from differing values under a recognized forbidden field name.

Unknown and permitted field values are not content-classified for sensitivity. Sensitive material must not be placed in any field.

14. VISIBILITY

Resolution and presentation are separate.

`reference_visibility_authorized = true -> VISIBLE`
`reference_visibility_authorized = false -> WITHHELD`

For a resolved withheld outcome, the summary neutralizes outcome-dependent fields:

`admission_state = WITHHOLD`
`claim_outcome = NONE`
`currency = NONE`
`payable_amount_minor = 0`
`outcome_id = NONE`
`result_id = NONE`
`reason_codes = [OUTCOME_WITHHELD]`

The reference tests:

`withheld PAYABLE summary == withheld NOT_PAYABLE summary`

for otherwise presentation-equivalent cases.

15. RECONSTRUCTION BUNDLE

Schema: `SLANG-CLAIMS-BUNDLE-1`

A bundle carries submitted input, normalized projection, deterministic result, contract identifiers, and `bundle_id`.

Bundle verification reconstructs the artifact from submitted input and requires exact canonical equality.

`bundle verification = deterministic reconstruction`

It does not establish source authenticity or operational authority.

16. COMPACT RECEIPT

Schema: `SLANG-CLAIMS-RECEIPT-1`

A receipt is a compact result-binding artifact. It does not contain the complete submitted input.

Receipt integrity checking validates:

- exact field set
- schema and version
- core, profile, ruleset, and canonicalization identifiers
- authority exclusions
- identifier forms and domain prefixes
- state, outcome, admission, and visibility invariants
- money-field types and arithmetic relations
- reason-code membership
- result and receipt identity relations

17. RECEIPT VERIFICATION SCOPES

Integrity-only command:

`--check-receipt-integrity RECEIPT.json`

Scope:

`SELF_CONSISTENCY_AND_DECLARED_INVARIANTS_ONLY`

It must report:

`BUNDLE_CORRESPONDENCE: NOT_CHECKED`

Full receipt verifier:

`--verify-receipt RECEIPT.json --against-bundle BUNDLE.json`

Scope:

`REQUIRES_EXACT_RECONSTRUCTION_BUNDLE`

It verifies the bundle, checks receipt integrity, rebuilds the expected receipt, and requires exact canonical equality.

`receipt integrity != bundle correspondence`
`bundle correspondence != source authenticity`
`source authenticity != payment authority`

A receipt must not be treated as a payment approval signal solely because an integrity command exits successfully.

18. STATE ATTESTATION

Schema: `SLANG-CLAIMS-ATTESTATION-1`

A state attestation provides a compact portable evidence surface for all resolution states, including non-result states.

It can represent:

`RESOLVED`
`INCOMPLETE`
`CONFLICT`
`FORBIDDEN`
`UNSUPPORTED`
`ABSTAIN`

The artifact binds contract, submission, result state, reason codes, diagnostics, available context/evidence identities, and fixed authority exclusions.

Integrity-only scope:

`SELF_CONSISTENCY_ONLY`

Correspondence scope:

`REQUIRES_ORIGINAL_INPUT`

Full attestation verification regenerates the attestation from the supplied input and requires exact canonical equality.

`attestation integrity != input correspondence`

25. COMMAND EXIT CONTRACT

`0 = requested command completed successfully`
`1 = self-test or artifact-verification failure`
`2 = runtime, input, JSON, I/O, or command-resolution error`

For resolution commands, exit `0` means the command executed. It does not mean `PAYABLE` or payment authorized.

26. BOUNDED CLAIM

`same admitted canonical claim structure + same versioned contract -> same bounded claim result`

`non-result state -> no forced PAYABLE outcome`
